# Архитектура

## Слои

Проект использует простую блочную архитектуру без сборочного фреймворка приложения:

- `app.js` — точка входа и hash-роутинг: `#/`, `#/chat`, `#/blog`, `#/blog/<slug>`;
- `components/nav` — шапка с переключением страниц;
- `components/home` — главная страница с описанием проекта;
- `components/chat` — чат, быстрые запросы, история диалога и потоковый вывод;
- `components/blog` — список статей и страница отдельной статьи;
- `data/posts.js` — статьи блога;
- `services/ollama.js` — единственная точка обращения к Ollama;
- `styles/base.css` — общие правила страницы;
- `docker-compose.yml` — инфраструктура локальной модели.

## Поток сообщения

1. Пользователь вводит текст или нажимает быстрый запрос.
2. `components/chat/chat.js` добавляет сообщение пользователя в DOM.
3. `services/ollama.js` формирует prompt из системных правил и последних четырёх сообщений.
4. Ollama возвращает NDJSON-поток.
5. Фрагменты ответа сразу отображаются в чате.
6. Перед отображением удаляются Markdown-символы выделения.
7. Полный ответ добавляется в историю текущего диалога.

## Ограничения

- История хранится только в памяти браузера: она сохраняется при переходе в блог и обратно, но исчезает после перезагрузки.
- Статьи блога статичны и редактируются в `data/posts.js`.
- Ollama вызывается напрямую из браузера, поэтому локальный сервер должен разрешать запросы с dev-сервера.
- Авторизация пользователей и серверное хранение данных не реализованы.
